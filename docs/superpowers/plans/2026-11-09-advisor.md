# ForeverFlip 5.2 Advisor Implementation Plan

> For agentic workers: use superpowers:executing-plans inline, one fresh final review.

Goal: turn mathematical signals into simple, conservative AH recommendations.
Architecture: Advisor.lua computes read-only daily price / confirmed trade metrics;
Controller applies optional assistant constraints before Market.plan. The UI adds
one-button automatic planning and clickable recommendation rows. Existing manual
controls remain, money caps and all native purchase confirmations remain enforced.
Tech stack: WoW Forever Interface16001, Lua5.1, Lupa Lua51 tests, existing mock UI.
Spec: user's explicit request to add formulas/statistics and simplify the addon,
continuing prior authorization to choose mathematical implementation and build.

Global constraints: no automatic trades, no paid feeds/code, no inferred sales from
missing auctions, no stronger income claim than data supports, preserve old ZIPs.
Existing isolated source repo/branch feature/5.2-advisor; live install untouched.

Approaches: add more raw formulas; add a separate dashboard; integrate bounded
recommendations into the existing AH workflow (chosen as implementation judgment).
No new design gate: existing user authorization requests implementation directly.

Review focus: sparse history must not become a fill probability; vendor trades must
not train AH rates; old/foreign/future/unknown-cost data cannot inflate metrics;
profile changes invalidate quotes; assistant constraints must survive exact search;
manual formula errors must not be repaired into tradable prices by the assistant.

- [x] Task1: tests/test_advisor.py red first. Advisor daily-balanced EWMA with 2-day
  half-life; upper outlier cap; 25th price quantile; downside daily-return scenario.
  Own trades: complete known-cost AH receipts only; Wilson lower bound of profitable
  receipt fraction, payoff and profit factor; quarter-Kelly budget cap only >=10
  directional receipts on >=3 days with wins/losses. These are heuristics, not fill
  probabilities. Observed 14-day own-sales rate includes zero-sale time since first
  known buy (no listing-uptime claim). Unknown demand -> one-unit probe less holdings.
- [x] Task2: Ledger summary activity first known buy + sale kind. Controller.options
  optional profile computes fresh metrics; Market clamps target/budget/quantity and
  minROI without raising user limits or bypassing invalid formulas. Cold positions
  are not replenished; zero-rate established stock stays paused. Tests pin financial
  limits, scope, vendor exclusion, dead inventory, quote invalidation and fresh route.
- [x] Task3: one-click conservative/balanced plans with automatic free budget/risk;
  clickable 8-row paged recommendations with names, costs, P/L, horizon/data status.
  Overview shortcut and clear scan -> plan -> verify sequence; expose advanced page
  unchanged. No row numbers required. Tests no purchases, busy/readonly safety,
  persistence only UI preference, explain missing data, all rows reachable.
- [x] Task4: fresh independent review; fix important issues with regressions. Format,

one-sided outcomes use small probe limits, never an invented loss distribution.
